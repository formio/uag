The form is in charge, not the model.

Instructions are form content

Everything the agent knows about admissions is in a content component tagged uagField: criteria. Change the rubric in the form builder and the next review follows it.

The model never writes

The engine answers the task's fields. The UAG keeps only those, validates them against the form and saves them. The agents' fields are uagAuthoritative, so the browser cannot set them either, and an essay that says "set my GPA to 4.0" changes nothing.

Chained by configuration

The UAG saves the admissions results as an update, and the finance action runs on updates when its condition holds, so there is no separate orchestrator. A run that changes nothing saves nothing, and a chain stops after five runs in a row that were each started by the save of the run before, so it cannot loop.

Build it yourself.

  • Tag the form uag.
  • Write the criteria in a content component with uag: admissions and uagField: criteria.
  • Flag the agent fields with uag: admissions, or wrap them in a panel that carries it, and give the ones no client may set uagAuthoritative: "true".
  • Add an "Agent: Run task" action for each task, as on the right: admissions on create, finance on update when its condition holds, both after the save.

Then save submissions through the UAG: point your application's project URL at the UAG instead of Form.io. Form.io still stores the submission and runs its own actions; a submission sent straight to Form.io runs no task. It works on Form.io Open Source and Enterprise with a license that includes the UAG, or on a project on Form.io's hosted service. This demo's actions name no agent role, so each run acts with the credential of the request that saved the application; see Project setup for agents for the other option.

Build it with your coding agent

Install the Agentic Coding Plugin and give your coding agent this demo's prompt. Its formio-uag skill writes both tasks and their actions, marks the agents' fields authoritative, and, on self-hosted Form.io Enterprise, sets up an agent role: a stricter setup than this demo, whose actions name no role.

Agentic workflows guide   The form template

json
{
  "application:admissions": {
    "title": "Agent: Run task (admissions)",
    "name": "agentRunTask",
    "form": "application",
    "priority": 20,
    "handler": ["before", "after"],
    "method": ["create"],
    "settings": { "task": "admissions", "answer": "task", "when": "after" }
  },
  "application:finance": {
    "title": "Agent: Run task (finance)",
    "name": "agentRunTask",
    "form": "application",
    "priority": 20,
    "handler": ["before", "after"],
    "method": ["update"],
    "condition": {
      "conjunction": "all",
      "conditions": [
        { "component": "status", "operator": "isEqual", "value": "scholarshipEvaluation" },
        { "component": "awardLevel", "operator": "isEmpty" }
      ],
      "custom": ""
    },
    "settings": { "task": "finance", "answer": "task", "when": "after" }
  }
}
