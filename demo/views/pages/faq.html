Frequently asked questions

What Agentic Forms are, what the Universal Agent Gateway needs to run, how the Agentic Coding Plugin builds them, and what you can build before you need a license.

What is the Universal Agent Gateway?

The UAG sits between AI agents and your Form.io project. Your forms become the instructions, guardrails and APIs agents work through: an agent discovers a form's fields, has every value checked against the form's own validation, and saves through the same permissions as any other Form.io client. The UAG is open source under the MIT license, and runs in your own environment.

It works with Form.io Open Source, a self-hosted Form.io Enterprise server, or a project on Form.io's hosted service. See How the UAG works.

How does the Agentic Coding Plugin fit in?

The UAG runs Agentic Forms. The Agentic Coding Plugin (@formio/ai) builds them: it gives coding agents that read skills, such as Claude Code, Cursor, Codex and Copilot, the Form.io MCP server and a skill library. Its formio-uag skill tags your forms, designs their tasks, deploys the UAG and its engines, and connects your application over MCP, the chat widget, Agent Input (@formio/uag-js filling a form from a description) or "Agent: Run task".

Install it with npx skills add formio/ai in your application's folder, or in Claude Code with /plugin marketplace add https://github.com/formio/ai.git and then /plugin install formio-ai@formio. The plugin is open source under the MIT license; what it builds follows the licensing below.

What is the difference between conversation forms and Agentic Formflow?

The difference is what the AI does: help a person fill in a form, or decide and fill in fields itself.

  • Conversation forms: a person fills in a form by talking. Either your agent (Claude, a chat app, any MCP client) runs the model and calls the UAG's MCP tools to discover forms, validate answers and submit, or you embed the chat widget in a page, and each turn is the form's agent/chat on the UAG, answered by one of the UAG's agent engines. Either way every answer is checked against the form, and nothing is submitted until the person confirms.
  • Agentic Formflow: the UAG decides and fills in fields itself, with the engines you enable, from tasks and criteria you define on the form. As a licensed feature it covers two patterns, agentic workflows and formflow: the Agent API, the "Agent: Run task" action, which runs a task when a submission is saved through the UAG (before the save, or after it with no client in the loop), and evaluating engines.

The conversation demo is a conversation form, embedded with the chat widget; the workflow and formflow demos are its two Agentic Formflow patterns.

What features are available to the Open Source server?

Everything except Agentic Formflow and the UAG's own database. With Form.io Open Source and an unlicensed UAG, any agent can read, validate and write a form's data, with the form as the rulebook:

What you can build with Open Source alone

  • Intake on any channel. The same form-driven conversation over SMS, Slack, Teams, email or a voice line; only the transport changes.
  • An internal staff assistant. "Find Jane's ticket and set the priority to high" is find_submissions and submission_update, with the signed-in user's own permissions.
  • Forms filled from documents. Your agent reads a PDF or an email, and submits through collect_field_data, so every value is checked against the form's rules.
  • Booking and catalog flows. fetch_external_data brings live options, such as appointment slots or products, into the conversation.
  • Questions about your data. "How many open claims came in this week?" is find_submissions without a search, which returns a count.
  • Validated bulk import. An agent moves legacy records in through the same validation, and reports the ones that fail.
  • Multilingual and accessible forms. The conversation can be in any language while the data is stored in the form's own values, and a voice front end makes a form usable without a screen.

What these leave to Agentic Formflow is work that must happen on the server, without a client in the loop, or be authoritative: workflows that run when a submission is saved, decisions re-checked before the save, engines you run and govern centrally, the record of which engine decided each value, and evaluation.

When do I need a license, and which one?
  • Agentic Formflow needs a license that includes the UAG, or a project on Form.io's hosted service, which runs under Form.io's own license.
  • A self-hosted Form.io Enterprise project needs a license that includes the UAG before the UAG will load it at all.
  • A license includes the UAG when it is an online license whose key has the uagServer scope, which allows a number of UAG servers (each project a UAG serves counts as one), or an offline license with the uag option, issued for the one project it serves.
  • The UAG's own database (MONGO), which remote MCP sign-in (MCP_OAUTH), run records in Action Logs and runs that survive a restart use, needs a license on every edition, the hosted service included. The database needs a license that includes the UAG, unless the project and the database are both on development hosts (localhost, *.local); Compose service names such as formio and mongo are not, so without a license give both services a *.local network alias, or run them on localhost. Without a license the UAG starts with those features off, and says why in its log.
  • Everything else, including conversation forms and every MCP tool marked "Available" in the table above, needs no license on Form.io Open Source or the hosted service.

Put the license in LICENSE_KEY, the same variable Form.io Enterprise reads, so one Form.io license that includes the UAG runs both. UAG_LICENSE still works, and is deprecated. See Licensing, or ask us for a trial.

Can I try Agentic Formflow without a license?

Yes, two ways:

  • Connect the UAG to a project on Form.io's hosted service (https://<project>.form.io). Agentic Formflow runs there with any engine, and /agent/capabilities reports reason: "hosted".
  • Enable only the stub engines (UAG_ENGINES=stub-decision,stub-agent). The Agent API and "Agent: Run task" actions then run anywhere, with placeholder answers, so you can build against it before you have model keys.

Or try every demo live on the Examples page.

Which AI models can I use?

For conversation forms over MCP, any agent that speaks MCP, with whatever model it runs. The chat widget uses the UAG's own agent engines. For the chat widget and Agentic Formflow, the official engines are jev (decisions), claude, openai (which also reaches OpenAI-compatible servers such as Ollama), grok and gemini, and you can host engines on a separate engine server or write your own with the Engine SDK. See Engines.

Where does my data go?

The UAG runs in your environment and talks to your Form.io project directly; it does not need a public address. Data leaves only to the models you choose: your agent's model for conversation forms over MCP, and the engines you enable for the chat widget and Agentic Formflow. Point an engine at a model on your own network to keep everything inside it. See Security.
