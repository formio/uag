# Changelog

## 2.0.0

The first release of the Agent API (1.14.0 was never published). Coming from 1.13, the new features are off until enabled, and existing MCP clients and conversation forms keep working. The Claude integration is retired, though `formio/uag-claude` 1.3.x keeps working against 2.0 until its webhooks move to the Agent API; see [MIGRATING-2.0.md](./MIGRATING-2.0.md). The appserver 2.16.0 upgrade (see Changed) brings three things to check: MCP clients sign in again once, a Form.io server with a self-signed certificate needs its CA trusted, and a module's template is now installed only at startup unless `TEMPLATE_SYNC=refresh`.

### Added

- **Agent API**: model-independent operations on a form's tasks. `/agent/extract` fills a task's fields from free text (`text`, or the task's input field); `/agent/decide` decides its closed-set fields and `/agent/generate` writes its open values, both from the data sent and saving nothing; `/agent/provide` fills a task in on a saved submission and saves once, for webhooks; `/agent/capabilities` reports the engines and which operations they serve. The UAG routes each field to an enabled engine — closed-set fields to a decision engine, open values to an agent engine — with fallback and timeouts, and extract streams results as each engine finishes. Forms are named, never sent. Responses carry an `X-Request-Id` header (the caller's own, when it sends one), except authentication failures. See the README's Agent API section.
- **Tasks**: a form's `uag` groups — a criteria component, an optional input and the fields it fills — are called tasks, and every operation takes an optional `task`. With none named, decide and generate run every task, each with its own criteria; extract runs every task with an input; provide uses the form's only task and refuses a form with several.
- **Agent API configuration** (module `config`): `engines` (engine instances to enable), `engineTypes` (engine types the application provides), `routing` (engine preference lists for `decision` and `value`, and `timeouts` per engine) and `agentApi`:
  - `threshold` (default 0.5) for Choice and Score answers, and `uncertainBand` (default `[0.2, 0.8]`) for yes/no answers and for whether the input addresses a field at all.
  - `timeout`: how long an engine call may take before the next engine is tried. Default 30000 ms; `routing.timeouts[engine]` overrides it.
  - `research.timeout` (default 120000 ms) and `research.maxIterations` (default 10), for agent engines researching with a task's tools.
  - `rateLimits.caller` (by operation) and `rateLimits.engine`.
- **Engines** are npm packages, each with its own provider SDK, enabled as named instances of a type: `UAG_ENGINES=jev,fast:claude,deep:claude` (or `config.engines`). With nothing named, no engine is enabled.
  - Official engines, each its own package: `@formio/uag-jev` (TypeSafe Jev decisions), `@formio/uag-claude` (Claude extraction and research; 1.x of this name was the retired integration), `@formio/uag-openai` (extraction and research on OpenAI through the Responses API, so current reasoning models can use tools, storing nothing at OpenAI, or on any server with OpenAI's chat completions API, such as Ollama, vLLM, LM Studio and OpenRouter; and, with `kind: decision`, decisions on OpenAI's Decisions API), `@formio/uag-grok` (xAI's Grok models) and `@formio/uag-gemini` (Google's Gemini models). The Grok and Gemini engines are built on the OpenAI engine's OpenAI-compatible core, `@formio/uag-openai/compatible`. The Docker images include them all.
  - A type is built in (`remote`, `stub-decision`, `stub-agent`), given by the application (`config.engineTypes`), or found as the installed package `@formio/uag-<type>` or `uag-engine-<type>`, from the UAG's installation and `UAG_ENGINE_PATH`. Nothing is ever installed at run time.
  - Each instance's settings come from its options, then `UAG_ENGINE_<NAME>_<SETTING>`, then the type's own variables (such as `CLAUDE_API_KEY`), then defaults. Startup fails, naming the instance, on an unknown type, a duplicate name, a missing setting or a failing engine, and secret settings never appear in errors.
  - `/agent/capabilities` lists each instance with its type, package and version.
  - The `remote` type reaches an engine hosted by `@formio/uag-engines` (image `formio/uag-engines`) over the remote engine protocol, so model keys and model traffic stay in that container: `UAG_ENGINES=claude:remote` with `UAG_ENGINE_CLAUDE_URL` and `UAG_ENGINE_CLAUDE_KEY`. It sends only the engine server key, never a Form.io credential. For research it also sends a scoped token, which the engine server uses to call the UAG's `/mcp`.
  - The Claude and OpenAI engines send every requested field as required, with an empty value for "not stated". Numbers and yes/no fields travel as strings and are converted back.
- **`uag` command** in the npm package: starts the UAG from the environment, with an optional module in `UAG_MODULE`. With it, an image with only some engines is the UAG plus those engine packages; see "Building a smaller image" in the README. The `formio/uag` image includes every official engine.
- **The demo site** (`demo/`), published at [ai.onform.io](https://ai.onform.io), replaces `examples/`: the product pages, Getting Started, the Developers documentation, and the Conversation Forms, Agentic Workflow and Agentic Formflow demos running live on one Form.io project and one UAG, each beside a flow viewer that shows the visitor every leg of their own runs. One Docker Compose stack (`demo/docker-compose.yml`) on the demo's project on Form.io's hosted service (`https://uag.form.io`), with a setup job, the UAG, the engine server, the flow proxy and the site, which is the only published service and relays the project's webhooks to the UAG; `docker-compose.enterprise.yml` holds the project on self-hosted Enterprise Form.io instead. Run locally without a UAG that can run Agentic Formflow, the examples say a license is needed to run them; `yarn demo:start` runs the site alone against a UAG of your own. Visitors are rate limited, the day's spend is capped, Turnstile can be required, and what they submit is deleted after a day. The custom module and the engine compose overrides moved to `demo/samples`; the e2e suites run the demo (`layer1.demo-*`, `layer3.demo-stack`).
- **Request ids end to end**: the UAG sends the Agent API request id to remote engines as `X-Request-Id`, and the engine server sends it on its research calls to `/mcp`, so a proxy can group every leg of one run. Only short tokens (`[A-Za-z0-9._:-]`, at most 128 characters) are used; the UAG replaces any other incoming id with its own.
- **Runs on a plain Form.io license**: the license is read from `LICENSE_KEY`, the variable (and license) the Form.io Enterprise and PDF servers use, with `@formio/appserver-core` 2.21. `UAG_LICENSE` is still read, and a feature is on when either license grants it; `LICENSE_KEY` is only checked when `UAG_LICENSE` is missing, unusable, or lacks `uag` for the endpoint. Startup logs which license enabled Agentic Formflow, and a refusal gives each license's reason.
- **Hosted Form.io projects need no license**: a UAG serving a project on Form.io's hosted service (`https://*.form.io`) loads it, and runs Agentic Formflow, without a license (with `@formio/appserver-core` 2.20). A self-hosted Enterprise project still needs one.
- **`@formio/uag-sdk`** (MIT): what engine packages are built with. It has the engine contract and `ENGINE_API_VERSION`, `defineEngine` with declared settings, `EngineError` for messages safe to show, the loader, the remote engine protocol, and a conformance check that runs from any test runner. A package built for another contract version is refused at startup, naming both versions.
- **Decision fields**: closed-set fields decided with a status and confidence; a field the input does not address stays empty instead of taking a forced answer; per-field confidence thresholds; and the task input role (`uagField: "input"`) with `uagContext`. New component properties: `uagEngine` (also on the task's criteria component), `uagTools` (on the criteria component: read-only tools the task may research with, none by default), `uagThreshold`, `uagUncertainBand`, `uagScale` with `uagOptionDescriptions`, `uagOrderCheck`, `uagConfidenceField`, `uagAuthoritative` and `uagAgentDecides` (an agent engine's uncalibrated answer is written on save, for workflows with no decision engine). Fields inside data grids and edit grids are left out of Agent API operations, and so is a field that is another field's `uagConfidenceField`. When a decision is `uncertain`, its `uagConfidenceField` is written just below the field's threshold, so a condition on "below the threshold" matches every uncertain decision.
- **`agent_decide` MCP tool**, returning a task's decision questions as structured JSON without calling a model.
- **`agent_provide` MCP tool**: the new name of `agent_provide_data`, consistent with `agent_decide`. Tool overrides under `toolOverrides.agent_provide` apply to it, and so do overrides written for `agent_provide_data` (except a rename).
- **`agentDecide` action** (setting `task`), re-deciding a task's decision fields on the server before save. A confident result is written (with its `uagConfidenceField`); a `uagAuthoritative` field the server cannot confirm (uncertain or missing) is cleared; other fields keep their value. When some fields cannot be decided at all (engine failure, timeout, rate limit, or no engine enabled), the save is refused with 503 (429 when every engine is over its rate limit) instead of clearing anything. Provenance is recorded in `metadata.uag.decisions[path]`, with `source` (`server`, `client`, `cleared` or `none`) and `serverValue`. The action runs only for saves that pass through the UAG.
- **`/agent/provide`**, for webhooks: decides the task's decision fields on the saved submission (reconciled the same way as the `agentDecide` action), generates its empty, visible value fields, and saves once — only when a field value changed or was cleared, so a webhook its own save triggers does nothing the second time. Generated values are never written over a value already there, and are recorded in `metadata.uag.generated`. The response lists the changed values in `written` and the cleared paths in `cleared`; a 422 with `details` means the reconciled submission would fail validation, and nothing is saved. It answers 503 (or 429) when fields cannot be answered at all, and runs again if the submission changed meanwhile (409 if it changes again), so a concurrent edit is not saved over. The save goes through the UAG, so the form's `agentDecide` action, if installed, runs on it too.
- **No write tools for models**: the UAG validates and saves every value itself. Extract and decide give models no tools; generate and provide give an agent engine only the read-only tools its task lists in `uagTools`, running with the caller's identity.
- **Admin credentials on `/agent/*`**: `x-token` / `x-admin-key` for webhooks and servers, refused from browsers.
- **Scoped tokens**: `/mcp` honors short-lived tokens, signed with `JWT_SECRET`, that carry the caller's identity and a task's read-only research tools, used by an engine server researching for a `remote` engine. `/mcp` never lists or allows a tool that may write with one. A token lasts as long as the research timeout; `/agent/*` refuses them.
- **`uag-eval`** (`--task`): measures decision accuracy against automation on labeled examples, for setting thresholds. With a real engine it needs a license (`LICENSE_KEY`) with the `uag` feature for the project URL given as `--project`; the stub engines need neither.
- **License**: the Agent API, the `agentDecide` action, `agent_decide` and `uag-eval` (Agentic Formflow) are Enterprise features. They need a Form.io license (`LICENSE_KEY`) with the `uag` feature for the project's endpoint, or a project on Form.io's hosted service (`https://*.form.io`), which runs under Form.io's license. A project on the UAG's own machine needs the license too. With only the stub engines enabled, work that calls them runs without either; `agent_decide`, which calls no engine, still needs one. Otherwise they answer `403` with `code: "license_required"`. `/agent/capabilities` reports `edition` and `formflow: { licensed, allowed, reason }` (`licensed`, `hosted`, `stub-engines` or `unlicensed`), and the UAG prints its edition at startup. MCP and conversation forms need no license.
- **`@formio/uag-renderer`**: Agent Input for formio.js forms and wizards (option `task`). It never overwrites what the user entered; empties the values it filled from an earlier input when the input changes; asks once more when its decisions show fields the form was hiding (a wizard page triage turns on); annotates fields drawn after their results arrived; and reports progress through `onStart`, `onResult`, `onDone` and `onError`.
- **The claims wizard** (the demo site's Agentic Formflow page, `/examples/formflow`): a claims-intake site for a fictional insurer, modeled on the ACORD auto and property loss notices, whose steps are chosen by triage and filled from the policyholder's description, with live progress as the agent works.

### Changed

- **Agentic Formflow needs a license or a hosted project, wherever the project runs** (with `@formio/appserver-core` 2.20). A project on the UAG's own machine (`localhost`, `*.test`, loopback) needs a license too. Conversation forms (the MCP tools) still run on Form.io Open Source with an unlicensed UAG, and the stub engines still run without a license. `formflow.reason` no longer reports `local-endpoint`. The `agent_provide` MCP tool (and `agent_provide_data`), the agentic workflow over MCP, needs the license or a hosted project too.
- The Agentic Workflow demo (formerly `examples/agentic-workflow`) runs on webhooks that call `/agent/provide`, with the UAG's own engines; the Claude integration container is no longer part of it. Because `/agent/provide` fills only a task's own fields, the finance task no longer sets `status` (the `scholarshipGranted` option is gone): its webhook fires while `status` is `scholarshipEvaluation` and `awardLevel` is empty, and the workflow ends when it fills `awardLevel`.
- Requires `@formio/appserver-core` 2.20.1, which provides Agentic Formflow as the `Formflow` export, and `@formio/appserver` 2.20.0. With 2.20.1 a UAG on a hosted project whose plan has no Submission Collections starts: the authorization codes resource is created without a collection of its own, instead of failing at startup. The UAG refuses to start, saying why, when an older core or a second copy of it is installed.
- The Agent API claims only its own endpoints under `/agent`, so a project form at the path `agent` is still served.
- An engine's own error message (which can carry provider details) is no longer returned to API callers: they get "the engine failed" with the request id, and the full error is logged. The UAG's own timeout, rate-limit and license messages, and errors an engine marks `expose: true`, are shown as before.
- Admin credentials (`x-token`, `x-admin-key`) on `/agent/*` are refused on any request a browser makes, including same-origin requests that carry no `Origin` header.
- The repository is a set of yarn workspaces: the UAG, the engine SDK, the engines and the engine server, sharing one lockfile. The engine packages pin their provider SDK versions.
- An Enterprise project accepts a license in either key format when it carries the `appserver` or the `uag` feature (`uag` includes `appserver`). A library-format key that carries neither, which loaded before, is now refused at startup with an error naming the missing feature. License endpoints, and the development names an Enterprise project may use without a license, are now compared exactly rather than by prefix.
- `@formio/appserver` 2.16.0 notes: 2.15.0 added the `extendRouter` hook the Agent API is mounted through, and security fixes that apply to the UAG:
  - The OAuth (PKCE) flow used by MCP clients only accepts a Form.io token that the UAG can verify, so a forged token can no longer get admin access. Unsafe `redirect_uri` schemes (such as `javascript:`) are refused.
  - Access and refresh tokens are now distinct, so MCP clients sign in again once after upgrading.
  - TLS certificates are now verified on the UAG's own requests to Form.io, and on the webhooks and email templates its actions send (Form.io's own webhook actions are unaffected). Deployments that use a self-signed certificate can set `NODE_TLS_REJECT_UNAUTHORIZED=0`, or trust their CA with `NODE_EXTRA_CA_CERTS`.

  2.16.0 makes the project, not a module's template, the source of truth:
  - A module's template is installed once at startup by default, instead of on every `PROJECT_TTL` refresh. The new `TEMPLATE_SYNC` setting chooses `boot` (the default), `refresh`, or `off`. Only what the project is missing is installed, and that now includes actions missing from forms the project already has; existing forms and actions are never changed.
  - A `PROJECT_TTL` refresh now reaches everything the UAG serves: forms added in Form.io are served and offered to agents, deleted forms and forms that lose their `uag` tag are dropped, and each form's routes run its current actions.

### Deprecated

- `UAG_LICENSE`, in favor of `LICENSE_KEY`. It still works, alone or alongside `LICENSE_KEY`, and the UAG logs a deprecation notice at startup when it is set. It will be removed in UAG 3.0.
- The `agent_provide_data` MCP tool, in favor of `agent_provide`. It is still listed and answers exactly as `agent_provide` does, so MCP clients and `formio/uag-claude` 1.3.x that call it keep working; the UAG logs one deprecation notice when it is first used.
- The name `persona` for a task: the Agent API, `agent_provide` (and `agent_provide_data`), `agent_decide`, the `agentDecide` action setting, the renderer option and `uag-eval --persona` still accept it, and `/agent/provide` still accepts `formName`. Sending both names with different values is refused with 400. They will be removed in a future major version.

### Removed

- The Claude integration (`integrations/claude`; `@formio/uag-claude` 1.x and `formio/uag-claude`), retired in favor of the Agent API and the engine server. The npm name `@formio/uag-claude` now carries the Claude engine, from 2.0.0. Its 1.3.x release keeps working against 2.0, and gets security fixes only, from the `1.x` branch. Move its webhooks from `/agent/claude/agent_provide_data` to `/agent/provide`; see [MIGRATING-2.0.md](./MIGRATING-2.0.md).
- Registering engines with `server.use({ engines })`: name them in `UAG_ENGINES` or `config.engines`, as packages or `config.engineTypes`.
- `examples/`: replaced by the demo site (`demo/`). The custom module and the engine compose overrides are in `demo/samples`, the flow viewer is the demo's flow proxy (`demo/flow`), and the images are in `demo/public/images`.

### Fixed

- Remote MCP clients (Claude Desktop through `mcp-remote`, claude.ai connectors) can authenticate to a UAG serving an Enterprise or hosted project (with `@formio/appserver-core` 2.20). The project's OAuth endpoints were served only under its name (`/<project>/.well-known/*`, `/<project>/auth/*`), while the UAG's discovery documents and its `/mcp` challenge name them at the root, so a client found none of them. A server for one project now answers them at the root too; the project path keeps working.
- `get_field_info` now lists a radio field's options. Its rule told the agent to choose one of the listed options, but none were listed, so an agent could save a value the field does not offer ("urgent" for a low/medium/high radio).
