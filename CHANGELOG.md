# Changelog

## 2.0.0-rc.4

The first release of the Agent API and of the "Agent: Run task" action (1.14.0 was never published). Coming from 1.13, the new features are off until enabled, and existing local MCP clients and conversation forms keep working. Remote MCP clients now need `MCP_OAUTH=true` and the UAG's own database (`MONGO`, licensed); `MONGO` no longer connects the UAG to a database for submissions; `BASE_URL` is optional; and the "Authorization Codes" resource is no longer created, so it can be deleted from the project. The Claude integration is retired, though `formio/uag-claude` 1.3.x keeps working against 2.0 until its webhooks move to Run task actions; see [MIGRATING-2.0.md](./MIGRATING-2.0.md). The appserver 2.16.0 upgrade (see Changed) brings three things to check: MCP clients sign in again once, a Form.io server with a self-signed certificate needs its CA trusted, and a module's template is now installed only at startup unless `TEMPLATE_SYNC=refresh`.

### Added

- **Agent API**: stateless, model-independent operations on a form's tasks, which read no stored submission and save nothing. They are under the form, as its submissions are: `{form}` is the form's path, or `form/{formId}`, under the project's URL on the UAG (the UAG's root on Form.io Open Source; `/{projectName}` or `/project/{projectId}` on Enterprise and the hosted service), so `POST https://uag.example.com/supportrequest/agent/decide`. `{form}/agent/extract` fills a task's fields from free text (`text`, or the task's input field); `{form}/agent/decide` decides its closed-set fields and `{form}/agent/generate` writes its open values, both from the data sent (decide with a `submissionId` answers 400); `GET /agent/capabilities`, at the UAG's root, reports the engines, which operations they serve, and whether durable runs (`durableRuns`) and remote MCP sign-in (`mcpOAuth`) are available. The UAG routes each field to an enabled engine — closed-set fields to a decision engine, open values to an agent engine — with fallback and timeouts, and extract streams results as each engine finishes. The form comes from the URL; a `form` in the body is ignored, and a form not tagged `uag` answers 404, as does an operation on an unknown form (in any letter case). Bodies are limited to 5 MB (413 over it). Responses carry an `X-Request-Id` header (the caller's own, when it sends one), except authentication failures. See the README's Agent API section.
- **Tasks**: a form's `uag` groups — a criteria component, an optional input and the fields it fills — are called tasks, and every operation takes an optional `task`. With none named, decide and generate run every task, each with its own criteria; extract runs every task with an input. A Run task action names its task.
- **Agent API configuration** (module `config`): `engines` (engine instances to enable), `engineTypes` (engine types the application provides), `routing` (engine preference lists for `decision` and `value`, and `timeouts` per engine) and `agentApi`:
  - `threshold` (default 0.5) for Choice and Score answers, and `uncertainBand` (default `[0.2, 0.8]`) for yes/no answers and for whether the input addresses a field at all.
  - `timeout`: how long an engine call may take before the next engine is tried. Default 30000 ms; `routing.timeouts[engine]` overrides it.
  - `research.timeout` (default 120000 ms) and `research.maxIterations` (default 10), for agent engines researching with a task's tools.
  - `rateLimits.caller` (by operation) and `rateLimits.engine`.
- **Engines** are npm packages, each with its own provider SDK, enabled as named instances of a type: `UAG_ENGINES=jev,fast:claude,deep:claude` (or `config.engines`). With nothing named, no engine is enabled.
  - Official engines, each its own package: `@formio/uag-jev` (TypeSafe Jev decisions), `@formio/uag-claude` (Claude extraction and research; 1.x of this name was the retired integration), `@formio/uag-openai` (extraction and research on OpenAI through the Responses API, so current reasoning models can use tools, storing nothing at OpenAI, or on any server with OpenAI's chat completions API, such as Ollama, vLLM, LM Studio and OpenRouter; and, with `kind: decision`, decisions on OpenAI's Decisions API), `@formio/uag-grok` (xAI's Grok models) and `@formio/uag-gemini` (Google's Gemini models). The Grok and Gemini engines are built on the OpenAI engine's OpenAI-compatible core, `@formio/uag-openai/compatible`. The Docker images include them all.
  - A type is built in (`remote`, `stub-decision`, `stub-agent`), given by the application (`config.engineTypes`), or found as the installed package `@formio/uag-<type>` or `uag-engine-<type>`, from the UAG's installation and `UAG_ENGINE_PATH` (each directory's own `node_modules`, never the folders above it, `NODE_PATH`, the working directory or Node's global folders). Nothing is ever installed at run time.
  - Each instance's settings come from its options, then `UAG_ENGINE_<NAME>_<SETTING>`, then the type's own variables (such as `CLAUDE_API_KEY`), then defaults. Startup fails, naming the instance, on an unknown type, a duplicate name, a missing setting or a failing engine, and secret settings never appear in errors.
  - `/agent/capabilities` lists each instance with its type, package and version.
  - The `remote` type reaches an engine hosted by `@formio/uag-engines` (image `formio/uag-engines`) over the remote engine protocol, so model keys and model traffic stay in that container: `UAG_ENGINES=claude:remote` with `UAG_ENGINE_CLAUDE_URL` and `UAG_ENGINE_CLAUDE_KEY`. It sends only the engine server key, never a Form.io credential. For research it also sends a scoped token, which the engine server uses to call the UAG's `/mcp`. When the engine server cannot be reached, callers are not told its URL, and a `url` with a user name or password is refused at startup. The engine server listens on `127.0.0.1` unless `HOST` says otherwise (its image sets `0.0.0.0`), logs every engine failure in one line, and shuts down gracefully on SIGTERM (`SHUTDOWN_TIMEOUT`, default 10000 ms).
  - The Claude and OpenAI engines send every requested field as required, with an empty value for "not stated". Numbers and yes/no fields travel as strings, keeping the field's description, and are converted back; a number written as an amount (`$4,250`) is read as 4250. The Grok and Gemini engines ask for string formats and patterns in words, so a field the input does not state stays empty instead of being invented to fit a pattern.
  - Provider settings go only to their provider: `OPENAI_API_KEY`, `OPENAI_ORG_ID`, `OPENAI_PROJECT_ID` and `OPENAI_CUSTOM_HEADERS` are sent only to OpenAI itself. An `openai` instance with a `baseURL` elsewhere, a proxy in front of OpenAI included, uses its own `UAG_ENGINE_<NAME>_API_KEY`, or sends no key.
- **`uag` command** in the npm package: starts the UAG from the environment, with an optional module in `UAG_MODULE`. With it, an image with only some engines is the UAG plus those engine packages; see "A smaller image" in the [Deployment guide](https://ai.form.io/developers/deployment#a-smaller-image). The `formio/uag` image includes every official engine.
- **The demo site** (`demo/`), published at [ai.form.io](https://ai.form.io), replaces `examples/`: the product pages, Getting Started, the Developers documentation, and the Conversation Forms, Agentic Workflow and Agentic Formflow demos running live on one Form.io project and one UAG, each beside a flow viewer that shows the visitor every leg of their own runs. One Docker Compose stack (`demo/docker-compose.yml`) of two services on the demo's project on Form.io's hosted service (`https://uag.form.io`): the UAG, with the JEV and Claude engines inside it, and the site, which is the only published service and runs the flow proxy inside it. `docker-compose.split.yml` moves the engines to the engine server and the flow proxy to its own service; `docker-compose.enterprise.yml` holds the project on self-hosted Enterprise Form.io instead, with a setup job that creates it. The workflow and claims demos save their submissions through the UAG, and their forms' Run task actions do the rest. Run locally without a UAG that can run Agentic Formflow, the examples say a license is needed to run them; `yarn demo:start` runs the site alone against a UAG of your own, and `yarn demo:start <port>` runs the whole demo on Form.io Enterprise on your machine, with its portal and a stage connected to the UAG. Visitors are rate limited, the day's spend is capped, Turnstile can be required, and what they submit is deleted after a day. The custom module and the engine compose overrides moved to `demo/samples`; the e2e suites run the demo (`layer1.demo-*`, `layer3.demo-stack`).
- **Request ids end to end**: the UAG sends the Agent API request id to remote engines as `X-Request-Id`, and the engine server sends it on its research calls to `/mcp`, so a proxy can group every leg of one run. Only short tokens (`[A-Za-z0-9._:-]`, at most 128 characters) are used; the UAG replaces any other incoming id with its own.
- **Runs on a plain Form.io license**: the license is read from `LICENSE_KEY`, the variable (and license) the Form.io Enterprise and PDF servers use, with `@formio/appserver-core` 2.21. `UAG_LICENSE` is still read, and a feature is on when either license grants it; `LICENSE_KEY` is only checked when `UAG_LICENSE` is missing, unusable, or lacks `uag` for the endpoint. Startup logs which license enabled Agentic Formflow, and a refusal gives each license's reason.
- **Hosted Form.io projects need no license**: a UAG serving a project on Form.io's hosted service (`https://*.form.io`) loads it, and runs Agentic Formflow, without a license (with `@formio/appserver-core` 2.20). A self-hosted Enterprise project still needs one.
- **`@formio/uag-sdk`** (MIT): what engine packages are built with. It has the engine contract and `ENGINE_API_VERSION`, `defineEngine` with declared settings, `EngineError` for messages safe to show, the loader, the remote engine protocol, and a conformance check that runs from any test runner. A package built for another contract version is refused at startup, naming both versions.
- **Decision fields**: closed-set fields decided with a status and confidence; a field the input does not address stays empty instead of taking a forced answer; per-field confidence thresholds; and the task input role (`uagField: "input"`) with `uagContext`. New component properties: `uagEngine` (also on the task's criteria component), `uagTools` (on the criteria component: read-only tools the task may research with, none by default), `uagThreshold`, `uagUncertainBand`, `uagScale` with `uagOptionDescriptions`, `uagOrderCheck`, `uagConfidenceField`, `uagAuthoritative` and `uagAgentDecides` (an agent engine's uncalibrated answer is written on save, for workflows with no decision engine). Fields inside data grids and edit grids are left out of Agent API operations, and so is a field that is another field's `uagConfidenceField`. When a decision is `uncertain`, its `uagConfidenceField` is written just below the field's threshold, so a condition on "below the threshold" matches every uncertain decision.
- **`agent_decide` MCP tool**, returning a task's decision questions as structured JSON without calling a model.
- **`agent_provide` MCP tool**: the new name of `agent_provide_data`, consistent with `agent_decide`. Tool overrides go under `toolOverrides.agent_provide`.
- **Proxy mode** (with `@formio/appserver-core` 2.24.0): the UAG forwards every submission it receives to Form.io as a fixed step of the request, and runs only its own actions (and a module's); Form.io runs its own (Save Submission, Login, Role, Webhook, Email, Group) on the forwarded request, so none runs twice. Applications can use the UAG's URL as their project URL: login and registration are forwarded, and Form.io's response, with its `x-jwt-token`, is passed back.
- **Form.io user tokens**: an `x-jwt-token` works against the UAG as against Form.io. It is verified with Form.io's `/current` (cached for 60 seconds, a refusal for 10) and forwarded unchanged, never re-signed. A token tied to a Form.io session (`jti`) is always checked with Form.io, even when the UAG shares Form.io's secret, so a logout takes effect.
- **"Agent: Run task" action** (`agentRunTask`), which runs one of the form's tasks on a submission sent to the UAG. Settings: **Task**, **Answer** (`task`, the whole task, or `decisions`, its decision fields only), **When** (`after` the save, in the background, or `before` it, while the submitter waits), **Agent role** and **Submitter roles** (both optional), with Form.io's methods and conditions. A submission sent straight to Form.io runs no task.
  - Before the save, the task runs on the submitted data, and the merged result is forwarded as the one save; the response is Form.io's. When decisions only cannot be answered, the save is refused with 503 (429 when every engine is over its rate limit) and nothing is stored; the whole task forwards without the answers it could not get.
  - After the save, the response returns at once; the task runs on the stored submission, and its results are saved as an update through the UAG, so the form's update actions, including other Run task actions, run on it, and tasks chain by their conditions. A run that changes nothing saves nothing. If the submission is saved meanwhile, the run starts again once on the new version, then fails as a conflict. Failures never affect the submitter's response; they are logged, and recorded when the UAG has its database. A chain stops, with a logged error, after 5 runs in a row that were each started by the save of the run before.
  - Fields a task owns and marks `uagAuthoritative: "true"`, decision and value fields alike (with their `uagConfidenceField`), are removed from what a client sends, for every Run task action on the form, whatever its method, conditions or timing; on an update they keep their stored value. Other fields stay editable, so a person's correction is kept. Provenance is recorded in `metadata.uag`.
  - Engines research with the identity of the user who submitted, never the agent role, and the submitter's `X-Request-Id` goes with every run, chained runs included. A chained action with no agent role acts as the submitter, never with the agent role of the run before it. A submitter's admin roles are left out of research, so their runs work and no admin token is ever signed.
  - Run task never substitutes the UAG's project API key for the caller: without an agent role it acts with the caller's own credential, which a run after the save holds in memory only. With an agent role and `JWT_SECRET` equal to Form.io Enterprise's, the UAG signs short-lived (5-minute) Form.io tokens that name the user it acts for: with only the agent role to save, and with the user's own roles, admin roles left out, to research and for chained actions with no agent role. They never carry an admin role, are never logged or stored, and reach an engine server only sealed inside a scoped token; if Form.io refuses them, the run fails saying `JWT_SECRET` must match. A create the caller's roles may not make is made by the agent, owned by the caller, when an action on create names an agent role the form grants Create All and the caller has one of its submitter roles; otherwise it is refused with 403. Not available on Form.io's hosted service, whose secret is not shared.
- **The UAG's own database** (optional): `MONGO` (a connection string, which can be the one Form.io uses), `UAG_DATABASE` (default `uag`, selected by name on the connection), `MONGO_CONFIG` and `TASK_RUN_RETENTION_DAYS` (default 90; 0 keeps records forever). It holds only `uag-meta`, `uag-authcodes` and `uag-taskruns`, never submissions; a database with `uag-*` collections the UAG did not create, or created by a newer UAG, stops startup. It needs a license that includes the UAG, unless the project and the database are both on development hosts; without one the UAG starts with the database features off, writes nothing, and says why. It enables remote MCP sign-in, run records, runs after the save that survive a restart (for actions with an agent role; one replica takes each run, under a lease, and only its own project's runs from a database other projects' UAGs share), and the license grace period (12 hours; without the database there is none).
- **Action Logs**: in the classic portal of a stage connected to the UAG (`PORTAL_SECRET`), a project's Action Logs list Form.io's entries and the UAG's run records together (title, task, state, fields saved, engines). In that stage, Form.io's action settings forms are fetched from Form.io with the caller's own credential; only the UAG's own actions are described by the UAG.
- **`MCP_OAUTH`**: `true` turns on OAuth sign-in for remote MCP clients (the authorize page, client registration and `/.well-known/*`). It needs a usable database; otherwise the UAG starts with it off and says why, and those endpoints answer 404. Authorization codes are stored by their SHA-256 hash, with the token they exchange for sealed under a key derived from the code. The 401 on `/mcp` names `resource_metadata` only when sign-in is on.
- **`TRUST_PROXY`**: Express's `trust proxy` (`true`, a hop count, or addresses), so the UAG reads its public URL from `X-Forwarded-Proto` and `X-Forwarded-Host`.
- **Module actions** can be marked `platform: true` when Form.io runs them; proxy mode skips them. A `before:access:<op>` hook can set `req.forwardAuth`, the identity a submission is checked and forwarded as, and `FormInterface.submit(submission, auth, request)` takes extra request fields.
- **No write tools for models**: the UAG validates every value and makes every write itself. Extract and decide give models no tools; generate and Run task (the whole task) give an agent engine only the read-only tools its task lists in `uagTools`, running with the caller's identity.
- **Credentials for a form's agent operations**: the same as the form's submissions, so an application that signs users in with Form.io needs no other token. The signed-in user's Form.io token (`x-jwt-token`) and a portal team member's remote token (`x-remote-token`) run the operation as that user or member, with Form.io's roles and permissions; UAG bearer tokens (`Authorization: Bearer`) work too. Server keys (`x-token`, `x-admin-key`) run as administrator, and are refused from browsers. A request with no credential is refused with 401, except where the form allows anonymous use.
- **Anonymous use of a form's agent operations**: a form that sets `uagAnonymous: "true"` and lets the Anonymous role create submissions answers visitors with no credential (otherwise 401, or 403 when Anonymous may not create). Anonymous requests are limited per client address (`AGENT_ANONYMOUS_RATE_LIMIT`, default 10 a minute) and in total (`AGENT_ANONYMOUS_TOTAL_RATE_LIMIT`, default 100 a minute), counted by each UAG process; over a limit they get 429 with `Retry-After`, before any engine is called. `0` for either turns anonymous use off.
- **Forms by id for every caller** (with `@formio/appserver-core` 2.24.0): a form is served at `form/{formId}`, under the project's URL, to every caller, user tokens and anonymous visitors included, as at its path, so a form's submissions and agent operations can be addressed by its id.
- **Portal team members through a connected stage**: a portal stage connected to the UAG works for team members (`x-remote-token` with `team_admin`, `team_write`, `team_read` or `team_access`) with Form.io's team permissions, not only for the project owner. Below `team_admin`, the project's settings, encrypted settings and billing are removed from what the UAG returns and forwards. See the Security page's "Portal team members".
- **Scoped tokens**: `/mcp` honors short-lived tokens, signed with `JWT_SECRET`, that carry the caller's identity and a task's read-only research tools, used by an engine server researching for a `remote` engine. `/mcp` never lists or allows a tool that may write with one. A token is honored only by the project it was issued for (with `@formio/appserver-core` 2.24.1), and lasts as long as the research timeout; a form's agent operations and `/agent/capabilities` refuse them. The caller's token travels sealed inside: a UAG bearer token, a signed-in user's Form.io token (`x-jwt-token`), or for a Run task the token it acts with, which `/mcp` verifies on every call the way the project verifies `x-jwt-token`, never as an administrator. Anonymous callers and portal team members below team admin carry none, so their remote research is refused.
- **`uag-eval`** (`--task`): measures decision accuracy against automation on labeled examples, for setting thresholds. With a real engine it needs a license (`LICENSE_KEY`) with the `uag` feature for the project URL given as `--project`; the stub engines need neither.
- **License**: the Agent API, the Run task action, `agent_decide` and `uag-eval` (Agentic Formflow) are Enterprise features, and run on Open Source too with a license. They need a Form.io license (`LICENSE_KEY`) with the `uag` feature for the project's endpoint, or a project on Form.io's hosted service (`https://*.form.io`), which runs under Form.io's license. A project on the UAG's own machine needs the license too. With only the stub engines enabled, work that calls them runs without either; `agent_decide`, which calls no engine, still needs one. Otherwise they answer `403` with `code: "license_required"`. `/agent/capabilities` reports `edition` and `formflow: { licensed, allowed, reason }` (`licensed`, `hosted`, `stub-engines` or `unlicensed`), and the UAG prints its edition at startup. MCP and conversation forms need no license. The UAG's database needs a license that includes the UAG on every edition, Form.io's hosted service included.
- **`@formio/uag-js`** (2.0.0, MIT): the UAG for formio.js applications. Register it once, `Formio.use(UAG('https://uag.example.com'))` (`import { UAG } from '@formio/uag-js'`, or the browser global `FormioUAG`), and render forms from their Form.io URLs as before: submissions of forms tagged `uag` are sent to the UAG, addressing each form by its id, and Agent Input is attached to those whose task has an input, with the signed-in user's Form.io token. Other forms, and every other request, still go to Form.io. Routing in the browser is not a security boundary: an agent role, the form's permissions and `uagAuthoritative` are. `UAG.attach(form, { formUrl, task, trigger, ... })` attaches Agent Input by hand. Agent Input never overwrites what the user entered; empties the values it filled from an earlier input when the input changes; asks once more when its decisions show fields the form was hiding (a wizard page triage turns on); annotates fields drawn after their results arrived; and reports progress through `onStart`, `onResult`, `onDone` and `onError`, including `error` events in the stream. A form loaded at a revision saves to the form; Agent Input sends the task of the input that triggered it; attaching again replaces the earlier attachment. With `requireReview: true`, the user must check each uncertain value (tick "Yes, this looks right" on its note, change it, or pick an alternative) before the wizard moves on or the form submits; the Agentic Formflow demo turns it on. TypeScript types are included (`index.d.ts`).
- **Chat** for conversation forms: `POST {form}/agent/chat` runs one stateless turn of a conversation that fills the form in. The client sends `messages`, the form's `data` and, optionally, the fields the person set in the form itself (`locked`, never asked for or changed); one agent engine answers through the ordinary agent-engine `extract` contract (no engine changes), with the form's collectable fields plus the turn's `-reply` and `-confirmed`; and the UAG answers with the `reply`, the values it accepted (`patch`, checked with the form's own validation; refused ones `invalid`), `remaining` fields (required, optional, and `unsupported` ones such as data grids, nested forms and uploads), `complete`, `confirmed` and the engine's `usage`. It never sets a task's fields, `uagAuthoritative`, hidden, disabled or calculated fields, stores nothing and never submits. In-process engines with `toolUse` may call the read-only `check_values` first; otherwise a refused value gets a corrected reply. It takes the form's agent credentials, needs create access, admits anonymous visitors on `uagAnonymous` forms within the anonymous limits, and is rate-limited as `agentApi.rateLimits.caller.chat`. Chat needs no Agentic Formflow license (on Form.io Open Source and hosted projects it runs with an unlicensed UAG; a self-hosted Enterprise project needs its license that includes the UAG, as for anything the UAG serves); `GET /agent/capabilities` reports `operations.chat`. New settings `agentApi.chat` (`engines`, `timeout`, `maxIterations`, `maxMessages`, `maxMessageLength`, `maxTranscriptChars`) and form properties `uagChat: "false"` and `uagChatInstructions`.
- **The chat widget** in `@formio/uag-js`: `Formio.createChat(element, src, options)` (also `createChat`, `UAG.createChat`, `FormioUAG.createChat`) renders a `uag` form as a chat, as `Formio.createForm` renders it as a form; registering `UAG()` adds the `chat` display. A formio.js form sits behind the chat: each turn's values are written into it, the person can open it to review or edit (the chat never overwrites their changes), and it submits through the UAG only after the person confirms a summary. Templated through formio.js templates (`uagChat`, `uagChatMessage`, `uagChatTyping`, `uagChatSuggestions`, `uagChatComposer`, `uagChatSummary`, `uagChatNotice`), translated through `i18n`, themed with `--uag-chat-*` CSS properties in `uag-js.css`, with `greeting`, `suggestions`, `markdown` (sanitized), `storage`, `chatUrl` and events `chatMessage`, `chatReply`, `chatComplete`, `chatError` and `chatReset`. See [Chat widget](https://ai.form.io/developers/chat).
- **The claims wizard** (the demo site's Agentic Formflow page, `/examples/formflow`): a claims-intake site for a fictional insurer, modeled on the ACORD auto and property loss notices, whose steps are chosen by triage and filled from the policyholder's description, with live progress as the agent works.

### Changed

- **Agent engines are told each field's validation** (with `@formio/appserver-core` 2.25): a field's rule now states its lengths, word counts, pattern, range, input mask and fixed date limits, for the Agent API, Run task and the chat alike. `required` is not stated, so an engine is never pushed to invent a value.
- **A Run task leaves out an answer the form refuses** (with `@formio/appserver-core` 2.25): a value the run wrote that fails the form's validation is reported `missing` (`failed validation: ...`) and not saved, as if no engine had answered, and the rest of the run is saved; a run after the save logs what it left out, and its record and Action Logs name the fields. Before, one such value made Form.io refuse the whole save: the person's submission before the save, or every answer of a run after it. The Agent API keeps such a suggestion, with that reason, for the person to correct.
- `CORS` takes several origins, separated by commas (with `@formio/appserver-core` 2.25).
- `/auth/token` returns no refresh token for `client_credentials` (RFC 6749, 4.4.3), and neither a token nor its refresh token outlives the Form.io login it wraps; `expires_in` says when the access token really ends (with `@formio/appserver-core` 2.25).
- The `formio/uag` image declares a `HEALTHCHECK` on `GET /status`.
- **One error shape for the Agent API**: every error from a form's agent operations and `/agent/capabilities` is `{ requestId, error, code }`, with the id in `X-Request-Id`, whatever refused the request — the project's authentication (which answered plain text), a credential or anonymous refusal (which answered `{ detail }`), the body parser (which answered HTML) or the operation. `code` is stable (`invalid_request`, `unauthorized`, `sign_in_required`, `forbidden`, `license_required`, `chat_disabled`, `form_not_found`, `payload_too_large`, `rate_limited`, `internal_error`, `engines_failed`, `no_engine`); clients that read `detail` should read `error`.
- **OAuth errors**: `/auth/token` and `/auth/authorize` answer RFC 6749 errors, `{ error, error_description }` (`invalid_request`, `invalid_client`, `invalid_grant`, `unsupported_grant_type`, `access_denied`), instead of empty or plain-text bodies, with `Cache-Control: no-store`; the sign-in page shows the reason when sign-in fails. A `401` from `/mcp` follows RFC 6750: `error="invalid_token"` in `WWW-Authenticate` when a token was sent, and `{ error, error_description }` as the body. Client secrets are compared in constant time.
- A submission refused by a Run task before the save always carries a `code` beside Form.io's `{ name, message }`.
- **An embedded UAG refuses to start without `--no-node-snapshot`**: `isolated-vm`, which runs form logic, can crash the process later without it. `assertNodeSnapshotDisabled` is exported; the `uag` command and the image already start Node with it.
- **`MAX_BODY_SIZE` defaults to `16mb`**, the limit Form.io itself applies, down from `100mb`: bodies are parsed before authentication.
- The UAG warns at startup when `JWT_SECRET` is not set (tokens then last only as long as the process), and when `MCP_OAUTH` is on with no `LOGIN_FORM` while `PROJECT` is a container address a browser cannot reach.
- **The UAG can be mounted under a path** (`app.use('/uag', ...)`): the sign-in page posts to a path relative to itself (with `@formio/appserver-core` 2.25.1). Remote MCP sign-in still needs the UAG at a host's root.
- **`JWT_EXPIRE_TIME` defaults to 60 minutes** (with `@formio/appserver` 2.25), down from 3600 (60 hours): a `client_credentials` token acts as the project administrator. Set it explicitly to keep the old lifetime.
- **Agentic Formflow needs a license or a hosted project, wherever the project runs** (with `@formio/appserver-core` 2.20). A project on the UAG's own machine (`localhost`, `*.test`, loopback) needs a license too. Conversation forms (the MCP tools) still run on Form.io Open Source with an unlicensed UAG, and the stub engines still run without a license. `formflow.reason` no longer reports `local-endpoint`. The `agent_provide` MCP tool (and `agent_provide_data`), the agentic workflow over MCP, needs the license or a hosted project too.
- The Conversation Forms demo embeds the service request form with `Formio.createChat`, and its turns are the UAG's `{form}/agent/chat`. The demo server's Claude tool loop over MCP is gone, and with it the demo's `@anthropic-ai/sdk` and `@modelcontextprotocol/sdk` dependencies, its `/api/conversation/chat` and `/api/conversation/forms` endpoints, and the site's `CHAT_MODEL`, `CHAT_MAX_TOKENS`, `CHAT_MAX_TOOL_ITERATIONS`, `CHAT_MAX_HISTORY_CHARS` and `CLAUDE_API_KEY` (the engine server's Claude answers the chat). `CHAT_FORMS` becomes `CHAT_FORM`, the one form the chat embeds; the site's routes under `/api/conversation/uag` stand in for the UAG for that form, adding the demo's bot check and budget, which charges each turn's `engine.usage`. The page links to the chat widget's documentation, and the e2e suites (`layer1.demo-conversation`, `layer1.demo-unlicensed`, `layer3.demo-stack`) run the chat against the scripted agent engine's chat turns or a real model.
- The Agentic Workflow demo (formerly `examples/agentic-workflow`) saves applications through the UAG, and its form's two Run task actions do the rest: admissions (the whole task, after the save, on create) and finance (the whole task, after the save, on update, when `status` is `scholarshipEvaluation` and `awardLevel` is empty). There are no webhooks and no webhook relay, and the Claude integration container is no longer part of it. A task fills only its own fields, so the finance task no longer sets `status` (the `scholarshipGranted` option is gone): the workflow ends when it fills `awardLevel`. The agents' fields are `uagAuthoritative`, the actions name no agent role (the deployed demo is on Form.io's hosted service), and the workflow runs on Open Source too, with a licensed UAG. The claims form has Run task (triage, decisions only, before the save, on create and update).
- `MONGO` is the UAG's own database. In 1.13 it connected the UAG to MongoDB directly, instead of routing submissions through Form.io's APIs; every submission now goes through Form.io.
- Remote MCP clients need `MCP_OAUTH=true` and the UAG's database. `/auth/token` (`client_credentials`) and API keys are always on, and need none of `BASE_URL`, `MONGO` or `MCP_OAUTH`.
- `BASE_URL` is optional: the UAG derives its public URL from each request (`Host`, or the forwarded headers with `TRUST_PROXY`), and `BASE_URL` overrides it.
- The Claude Desktop sample (`demo/samples/custom-module`) uses `MCP_OAUTH` with `MONGO` (on the `formio.local` and `mongo.local` aliases, development hosts, so no license is needed) and `TRUST_PROXY`, with no `BASE_URL`.
- Requires `@formio/appserver` 2.25.2, the UAG's only Form.io server dependency: it brings `@formio/appserver-core`, which provides Agentic Formflow as the `Formflow` export and proxy mode, and marks `save`, `login` and `role` as platform actions. The UAG reaches core only through `@formio/appserver`, so the two always share one copy, and refuses to start, saying why, when that copy is older than 2.25.2.
- The Agent API claims only `/agent/capabilities` at the UAG's root, so a project form at the path `agent` is still served.
- An engine's own error message (which can carry provider details) is no longer returned to API callers: they get "the engine failed" with the request id, and the full error is logged. The UAG's own timeout, rate-limit and license messages, and errors an engine marks `expose: true`, are shown as before.
- Admin credentials (`x-token`, `x-admin-key`) on a form's agent operations and `/agent/capabilities` are refused on any request a browser makes, including same-origin requests that carry no `Origin` header.
- The repository is a set of yarn workspaces: the UAG, the engine SDK, the engines and the engine server, sharing one lockfile. The engine packages pin their provider SDK versions.
- An Enterprise project accepts a license in either key format when it carries the `appserver` or the `uag` feature (`uag` includes `appserver`). A library-format key that carries neither, which loaded before, is now refused at startup with an error naming the missing feature. License endpoints, and the development names an Enterprise project may use without a license, are now compared exactly rather than by prefix.
- `@formio/appserver` 2.16.0 notes: 2.15.0 added the `extendRouter` hook the Agent API is mounted through, and security fixes that apply to the UAG:
  - The OAuth (PKCE) flow used by MCP clients only accepts a Form.io token that the UAG can verify, so a forged token can no longer get admin access. Unsafe `redirect_uri` schemes (such as `javascript:`) are refused.
  - Access and refresh tokens are now distinct, so MCP clients sign in again once after upgrading.
  - TLS certificates are now verified on the UAG's own requests to Form.io. Deployments that use a self-signed certificate can set `NODE_TLS_REJECT_UNAUTHORIZED=0`, or trust their CA with `NODE_EXTRA_CA_CERTS`.

  2.16.0 makes the project, not a module's template, the source of truth:
  - A module's template is installed once at startup by default, instead of on every `PROJECT_TTL` refresh. The new `TEMPLATE_SYNC` setting chooses `boot` (the default), `refresh`, or `off`. Only what the project is missing is installed, and that now includes actions missing from forms the project already has; existing forms and actions are never changed.
  - A `PROJECT_TTL` refresh now reaches everything the UAG serves: forms added in Form.io are served and offered to agents, deleted forms and forms that lose their `uag` tag are dropped, and each form's routes run its current actions.

### Deprecated

- `UAG_LICENSE`, in favor of `LICENSE_KEY`. It still works, alone or alongside `LICENSE_KEY`, and the UAG logs a deprecation notice at startup when it is set. It will be removed in UAG 3.0.

### Removed

- The `agent_provide_data` MCP tool: use `agent_provide`, which takes the same arguments. The retired `@formio/uag-claude` 1.3.x integration's `agent_provide_data` webhooks therefore need UAG 1.x; move them to Run task.
- The name `persona` for a task, everywhere: the MCP tools take `task`, `uag-eval` refuses `--persona`, and the Agent API refuses a body that names `persona` and no `task`.
- The Claude integration (`integrations/claude`; `@formio/uag-claude` 1.x and `formio/uag-claude`), retired in favor of the Agent API and the engine server. The npm name `@formio/uag-claude` now carries the Claude engine, from 2.0.0. Its 1.3.x release gets security fixes only, from the `1.x` branch; its `agent_provide_data` webhooks need UAG 1.x. Replace its webhooks to `/agent/claude/agent_provide_data` with Run task actions; see [MIGRATING-2.0.md](./MIGRATING-2.0.md).
- The "Authorization Codes" resource the UAG created in the project, for remote MCP sign-in. Its codes are in the UAG's database now; delete the resource.
- `/agent/provide` (with its `formName` alias) and the `agentDecide` action, from earlier builds of 2.0: replaced by Run task (after the save for the first, decisions only before the save for the second). The webhook pattern built on `/agent/provide` goes with them.
- Registering engines with `server.use({ engines })`: name them in `UAG_ENGINES` or `config.engines`, as packages or `config.engineTypes`.
- `examples/`: replaced by the demo site (`demo/`). The custom module and the engine compose overrides are in `demo/samples`, the flow viewer is the demo's flow proxy (`demo/flow`), and the images are in `demo/public/images`.

### Fixed

- The OAuth discovery document lists every grant `/auth/token` accepts (`authorization_code`, `refresh_token`, `client_credentials`), so a client knows it may refresh (with `@formio/appserver-core` 2.25.2). It listed only `authorization_code`.
- An action whose conditions name an operator Form.io does not know is skipped, and the UAG logs why once (with `@formio/appserver-core` 2.25.1). Form.io's condition check counts an unknown operator as a condition that holds, so a typo ran a Run task on every save, and on update in a loop.
- Instances starting together no longer fail on the module template: when another instance installed it first, Form.io refused the second import and the instance exited, and refused its actions as duplicates, which was logged as an error (with `@formio/appserver-core` 2.25.1).
- The `uag*` switches (`uagAuthoritative`, `uagAgentDecides`, `uagScale`, `uagOrderCheck`, `uagAnonymous`, `uagChat`) accept JSON booleans and any letter case. `uagAuthoritative: true` written as a boolean was ignored, so clients could set a field a task owns.
- `uag` on a Columns or Table component makes the inputs inside it the task's fields; it registered an empty field instead.
- A run after the save that cannot load the submission says the user it acts as may not be able to read it, not only that it was not found.
- Remote MCP clients (Claude Desktop through `mcp-remote`, claude.ai connectors) can authenticate to a UAG serving an Enterprise or hosted project (with `@formio/appserver-core` 2.20). The project's OAuth endpoints were served only under its name (`/<project>/.well-known/*`, `/<project>/auth/*`), while the UAG's discovery documents and its `/mcp` challenge name them at the root, so a client found none of them. A server for one project now answers them at the root too; the project path keeps working.
- A submission saved through the UAG no longer runs the form's Form.io actions (webhook, email, login, role, group) twice, once in the UAG and again at Form.io.
- `get_field_info` now lists a radio field's options. Its rule told the agent to choose one of the listed options, but none were listed, so an agent could save a value the field does not offer ("urgent" for a low/medium/high radio).
